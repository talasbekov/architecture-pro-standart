### <a name="_qmphm5d6rvi3"></a>**Решение**

Для обеспечения консультаций клиентов по актуальным депозитным ставкам во внутреннем и партнёрском кол-центрах в рамках MVP принято решение о централизации хранения ставок и их распространении из банковской системы.
Источник истины по депозитным ставкам размещается внутри банка — в АБС либо в выделенном модуле ставок, интегрированном с АБС. Все обновления ставок выполняются сотрудниками бэк-офиса и фиксируются в банковской системе как актуальная версия.
Для внутреннего кол-центра реализуется интеграция с банковской системой, позволяющая получать и отображать актуальные ставки в интерфейсе операторов. Это обеспечивает возможность оперативных консультаций клиентов без использования Excel-файлов и ручных расчётов.
Для партнёрского кол-центра, работающего во внешней информационной системе и не поддерживающего API-интеграции, выбран файловый способ передачи данных. Банковская система формирует файлы с актуальными депозитными ставками и передаёт их партнёру по согласованному защищённому каналу. Партнёрский кол-центр загружает полученные файлы в свою систему и использует их для консультаций клиентов.
Такое решение выбрано с учётом следующих факторов:
- отсутствует возможность прямых API-вызовов со стороны партнёрского кол-центра;
- необходимо минимизировать нагрузку на АБС;
- требуется быстрое масштабирование консультаций при росте числа звонков;
- важно использовать существующие технологии банка и не внедрять сложные новые платформы в рамках MVP.

Диаграммы:
- C4 Context: C4-Context-Deposit-Rates-MVP.puml
- C4 Component: C4-Component-Deposit-Rates-MVP.puml

Диаграмма контекста показывает взаимодействие банковской системы со внутренним и партнёрским кол-центрами в части передачи депозитных ставок. Диаграмма компонентов детализирует внутреннюю архитектуру решения, включая модуль управления ставками, механизм экспорта данных и интеграции с системами кол-центров.
Принятое архитектурное решение позволяет обеспечить актуальность данных, снизить операционные риски, подготовить систему к росту нагрузки и создать основу для дальнейшей автоматизации процессов на горизонте года.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

- Прямая интеграция системы кол-центра с АБС для получения ставок
В рамках данного варианта система кол-центра напрямую обращалась бы к АБС за актуальными депозитными ставками.
Не выбрано, так как АБС уже перегружена, масштабируется только вертикально и не предназначена для обработки большого количества онлайн-запросов. Прямая интеграция увеличила бы риски отказов и нарушила требования по изоляции АБС от дополнительных нагрузок.
- Передача ставок в партнёрский кол-центр через API
Альтернативным решением могла бы быть реализация API для передачи ставок во внешнюю систему партнёрского кол-центра.
Не выбрано, поскольку партнёрский кол-центр не поддерживает API-интеграции и готов принимать данные только в файловом виде. Реализация API также потребовала бы дополнительных мер по безопасности и сопровождению.
- Продолжение использования Excel-файлов и ручной рассылки ставок
Ставки могли бы по-прежнему формироваться в Excel и рассылаться сотрудникам кол-центра вручную.
Не выбрано, так как такой подход не масштабируется, приводит к использованию неактуальных данных, увеличивает операционные риски и не решает проблему роста количества обращений клиентов.

**Недостатки, ограничения, риски**

- На этапе MVP обновление и распространение ставок остаётся зависимым от внутренних процессов банка и ручных действий сотрудников бэк-офиса.
- Файловый способ передачи данных в партнёрский кол-центр не обеспечивает мгновенного обновления ставок и может приводить к кратковременной работе с устаревшей информацией.
- Отсутствие API-интеграции с партнёрским кол-центром ограничивает возможности автоматизации и мониторинга использования ставок.
- АБС остаётся узким местом архитектуры из-за ограничений на масштабирование и высокую нагрузку.
- Возможны задержки обновления ставок при росте числа изменений или при сбоях файлового канала передачи.
- Качество консультаций в партнёрском кол-центре зависит от корректности загрузки и использования полученных файлов со ставками.

### <a name="_bjrr7veeh80c"></a>**Список крупных задач по системам**

АБС / Модуль ставок
- Централизация хранения депозитных ставок (отказ от Excel).
- Реализация механизма обновления и подтверждения ставок бэк-офисом.
- Формирование актуальной версии ставок (версия, дата, время).
- Предоставление ставок для внутреннего использования (экспорт / интеграция).
- Обеспечение минимальной нагрузки на основную БД АБС.

Система кол-центра банка
- Интеграция с источником депозитных ставок банка.
- Отображение актуальных ставок в интерфейсе операторов.
- Обновление ставок без участия операторов.
- Контроль актуальности используемых данных.
- Обучение операторов работе с новым функционалом.

Партнёрский кол-центр
- Реализация приёма файлов со ставками от банка.
- Загрузка и обновление ставок во внутренней системе партнёра.
- Контроль версии и актуальности полученных файлов.
- Организация процесса замены устаревших данных.
- Инструкции для операторов по работе со ставками.

Интеграция и эксплуатация
- Настройка защищённого файлового канала передачи данных.
- Логирование фактов передачи и обновления ставок.
- Мониторинг успешности передачи файлов.
- Документирование формата файлов и процесса обновления ставок.
- Подготовка к масштабированию при росте нагрузки.
